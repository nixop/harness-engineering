# ADR-002: Front Relay with the API gateway

**Status:** Accepted
**Date:** 2026-03-04
**Author:** Pavel Grishin
**Deciders:** Relay weekly sync, 2026-03-02

## Context

Callers reach Relay directly through an internal load balancer with a shared API key. We want authentication per caller, per-route timeouts and retries, and one place to see traffic. The account's API gateway already fronts two other services.

## Options considered

- Keep the load balancer and add auth in the service
- Front Relay with the API gateway, routes and policies in the gateway nested stack (chosen)

## Decision

Front Relay with the API gateway; the gateway and its routes are defined in the gateway nested stack.

### Timeouts

The integration timeout on every Relay route is 10 seconds, chosen as a round number above the p99 of POST /deliver at intake (1.8 s).

### Retries

Retries are disabled on POST /deliver until idempotency keys exist, because a retried delivery can reach a customer twice. Read routes may retry twice. When retries are enabled they will be governed by a retry budget set in the gateway policy.

## Consequences

Callers switch from relay.internal to the gateway hostname. Timeouts and retries become gateway policy rather than service code; the values are set in the sections below and may change by later decisions.
