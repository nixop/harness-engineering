# ADR-001: Migrate infrastructure code from Terraform to CloudFormation

**Status:** Superseded (superseded by ADR-004)
**Date:** 2026-01-14
**Author:** Pavel Grishin
**Deciders:** Relay weekly sync, 2026-01-12

## Context

Relay's infrastructure is described in Terraform 0.12 modules that nobody has touched since 2024. The rest of the AWS account is managed with CloudFormation: the deployment pipeline, drift detection and IAM boundaries are all built around stacks. Keeping one service on a different tool means a second pipeline, no drift detection and a separate set of permissions.

## Options considered

- Upgrade Terraform in place (cheapest; keeps Relay the odd one out)
- Move to CloudFormation, importing resources without recreation (chosen)
- Move to CDK (CloudFormation underneath, but a fourth language in the team)

## Decision

Migrate Relay infrastructure code from Terraform to CloudFormation, module by module, finishing by end of Q1.

Objection recorded from Timur Aliev.

## Consequences

Every module is imported into a stack rather than recreated, networking last because of cross-account peering. Terraform state is kept until the last module moves. The architect's objection is recorded: the migration costs a quarter and CloudFormation handles modules worse than Terraform.
