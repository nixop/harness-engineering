# ADR-004: Hybrid IaC: Terraform for networking, CloudFormation for application stacks

**Status:** Accepted, supersedes ADR-001
**Date:** 2026-04-22
**Author:** Sergey Belov
**Deciders:** Relay weekly sync, 2026-04-20

## Context

Three months into ADR-001, the networking module was the last to move and the hardest: cross-account peering and DNS delegation need custom resources in CloudFormation, while the same networking is already expressed natively in the Terraform the network team maintains for the whole company.

## Options considered

- Finish the migration as decided in ADR-001
- Hybrid: networking stays in Terraform, application stacks in CloudFormation (chosen)

## Decision

Hybrid IaC: networking (VPC, peering, DNS) stays in Terraform; application stacks are CloudFormation.

Objection recorded from Pavel Grishin.

## Consequences

Supersedes ADR-001. The boundary is fixed: VPC, peering and DNS in Terraform; data, compute and gateway stacks in CloudFormation. Both sides run drift detection. Terraform state is cleaned of resources already imported into stacks.
